# Правила разработки

- Стек: Python 3.12, Django 5.2, Poetry 2.2.1.
- Используйте существующий `poetry.lock`; не обновляйте зависимости без необходимости.
- Сначала изучайте существующий код и тесты.
- Вносите минимальные обоснованные изменения.
- Пишите автоматические тесты для нового поведения.
- Перед завершением выполняйте `poetry run python manage.py check` и `poetry run python manage.py test`.
- Не добавляйте секреты и реальные `.env` в Git.
- Не подключайтесь к production-серверу и production-БД.
- Не выполняйте самостоятельный деплой.
- Не удаляйте данные и не выполняйте опасные миграции.
- После выполнения предоставляйте отчёт об изменениях, тестах и рисках.
- Используйте существующий checkout в изолированной облачной задаче; создавайте Git worktree только по явному запросу пользователя.
